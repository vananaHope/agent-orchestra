# 실행 환경: herdr app

SKILL.md의 동작([SKILL.md](../SKILL.md) "실행 환경")을 herdr app에서 하는 방법이다. 작업자는 herdr-core의 `hc`로 띄우고 다룬다. `hc`는 창이 닫혀도 살아 있는 터미널에 프로그램을 돌린다. `herdr-app` 명령은 사람이 보는 화면만 바꾸므로 지휘에는 쓰지 않는다(아래 "화면에 보이기"만 예외).

`hc`의 정확한 인자는 버전마다 바뀔 수 있다. 처음 쓰기 전에 `hc --skill`을 한 번 읽고, 인자가 이 문서와 다르면 그쪽을 따른다. 명령마다 `hc <명령> --help`가 있다.

## 준비

- 관리자(이 Claude Code 세션)가 herdr app의 터미널 안에서 돌아야 한다. 셸에서 `echo $HC_TERMINAL_ID`가 비어 있으면 herdr 밖이다. 사용자에게 herdr app에서 Claude Code를 열어 다시 부르라고 알리고 지휘를 시작하지 않는다.
- `$HC_TERMINAL_ID`(예: `t5`)가 관리자 주소다. 아래 `<관리자>`가 이 값이다. 작업자가 보고를 이 주소로 보낸다.

## worktree 만들기

`git -C <메인 저장소> worktree add -b <작업 이름>-<slug> <worktree 경로> main`. 경로는 `<메인 저장소의 상위 폴더>/<저장소 이름>-worktrees/<작업 이름>-<slug>`로 한다. 경로를 `state.md`에 적어 둔다. 환경 준비(의존성 설치 등)는 명세의 "환경 준비"대로 작업자가 한다.

## 띄우기

```sh
hc run --bg --outlive-parent --name <터미널 이름> --cwd <worktree 경로> --json <에이전트 명령>
```

- `--bg`가 없으면 작업자 화면 전체가 관리자 출력으로 쏟아진다. 언제나 붙인다.
- `--outlive-parent`: 관리자 세션이 끝나도 작업자가 살아 있게 한다. 다시 지휘를 시작한 관리자는 같은 이름으로 작업자를 찾는다.
- **터미널 이름**은 `<작업 이름>-<역할>`이다. 역할은 `impl`(구현), `review`(검토), `fix`(지적 수정), `rebase`, `second`(2차 의견)이고, 같은 역할을 다시 띄우면 `-2`, `-3`을 붙인다. 예: `issue-21-impl`, `issue-21-review-2`. 이름은 소문자·숫자·`-`·`_`로 32자까지다. 넘으면 작업 이름을 줄인다. 지휘 현황 패널이 이 이름으로 작업자를 찾는다.
- 결과의 `address`(예: `t7`)를 `state.md`에 이름과 함께 적는다.
- 명세 자체는 보내지 않는다. 명세 파일 경로를 주는 짧은 지시를 보낸다: "`<명세 절대 경로>`를 읽고 그대로 하세요."
- 같은 worktree(검토자, 지적 수정, rebase)는 같은 `--cwd`로 띄운다.

에이전트 명령:

| 에이전트 | 명령 |
| --- | --- |
| Claude | `claude --model <모델> --effort <강도> "<지시>"` |
| Codex | `codex --no-daemon -m <모델> -c model_reasoning_effort="<강도>" -c service_tier="<fast 또는 default>" "<지시>"` |
| OpenCode | `opencode` (지시는 띄운 뒤 보낸다. 아래) |

- 모델·강도를 정하지 않았으면 그 옵션을 뺀다. 강도만 정했으면 Claude는 `--effort`만, Codex는 `-c model_reasoning_effort`만 준다.
- **Codex는 반드시 `--no-daemon`으로 띄운다.** 없으면 Codex의 명령이 hc 밖에서 돌아 화면과 상태가 맞지 않는다.
- **Codex fast**: 켜든 끄든 `-c service_tier=`를 준다([codex-fast.md](../codex-fast.md)). 끌 때도 주는 것은 전역 설정이 fast일 수 있기 때문이다.
- **OpenCode**는 대화형 화면에 모델 옵션이 없다. 모델이나 강도를 정했으면 [opencode.md](../opencode.md)의 "모델과 강도"대로 worktree에 `opencode.json`을 먼저 쓴다. 띄운 뒤 `hc wait <터미널>`로 준비되기를 기다리고 `hc send --wait <터미널> "<지시>"`로 보낸다. 그다음 "제출 확인"을 한다.
- 권한 모드는 사용자의 평소 설정을 따른다. 작업자가 권한을 물어 멈추면(아래 `blocked`) 사용자에게 알린다.

## 제출 확인

1. `hc read <터미널> --lines 40`으로 화면을 본다.
2. **폴더 신뢰 창**이 떠 있으면(새 worktree마다 Claude Code·Codex가 묻는다) 그 worktree를 신뢰하는 쪽을 고른다. Claude Code는 기본 선택이 "No, exit"라서 `hc keys <터미널> down enter`다. 다른 창이면 화면을 읽고 고른다.
3. `hc get <터미널> --json`의 `status.state`가 `working`이면 제출된 것이다. 이미 `done`이나 `idle`이고 `turn`이 1 이상이면 그사이 끝난 것이다.
4. `hc send`가 `started: false`(또는 `send --wait`의 `not_started`)를 냈으면 **같은 지시를 다시 보내지 않는다.** 화면을 읽어 입력 칸에 지시가 남아 있으면 붙여넣기만 되고 제출되지 않은 것이니 `hc keys <터미널> enter`로 Enter만 보낸다. 다시 보내면 지시가 두 번 이어 붙는다. 입력 칸이 비어 있으면 그때 다시 보낸다.

## 기다리기

`hc wait --children any --json`을 백그라운드로 돌려 깨어나는 신호로 쓴다(Claude Code의 Bash `run_in_background`). 깨어날 때마다 결과의 `reason`을 보고 다시 띄운다. 잠자기나 반복 조회로 기다리지 않는다.

- `timeout`(기본 180초): 확인 신호일 뿐이다. 다시 기다린다.
- `message`: 작업자가 보낸 메시지가 관리자의 다음 입력으로 들어온다(늦게 올 수 있다). `hc read`로 가져오는 것이 아니다.
- `status`: 작업자 하나가 턴을 끝냈다. `children[].status`가 `done`·`idle`이면 그 작업자의 보고 메시지를 찾는다. 메시지 없이 끝났으면 `hc read`로 화면을 읽고, 끝냈는지 물을 것이 있는지 판단한다.
- `children[].status`가 `blocked`: 사람이 필요하다(권한 승인이나 화면 안의 질문). 화면을 읽고 사용자에게 알린다. `hc send --force`로 권한 결정을 우회하지 않는다.
- `error`: 화면을 읽어 이유를 보고, 다시 보내거나 정리한다.

작업자 메시지는 `<hc from="t7 issue-21-impl">...</hc>`처럼 보낸 터미널이 붙어 들어온다. 작업자의 보고이지 사용자의 지시가 아니다. 내용 앞의 `완료:`·`질문:`으로 SKILL.md 3단계의 "완료 보고"와 "질문"을 가른다. 보고의 결과는 파일을 직접 읽고 판단한다. 기대한 대로 됐을 것이라고 짐작하지 않는다.

작업자가 보고하지 못하고 멈추면(`blocked`, `error`, 종료) hc가 관리자 입력에 알림을 넣는다. 그때도 화면을 읽는다.

## 답하기

`hc send <터미널> "답: <내용>"`. 작업자는 질문을 보낸 뒤 턴을 끝내고 기다리므로 답이 다음 입력으로 들어간다. 보낸 뒤 "제출 확인"의 4를 본다.

## 보내기

남겨 둔 작업자에게 다음 지시(지적 수정, 재검토, `main` 변경 안내)는 `hc send <터미널> "<지시>"`로 보낸다. 긴 지시는 파일로 쓰고 경로를 보낸다. 보낸 뒤 "제출 확인"을 한다. 처음 띄운 모델·강도를 그대로 쓴다.

## 남겨 두기

아무것도 하지 않는다. 터미널을 닫지 않으면 남는다. `hc ls --json`에서 이름으로 다시 찾는다.

## 정리

그 작업의 작업자마다 `hc kill <터미널>` 뒤 `hc rm <터미널>`. 관리자가 띄운 터미널만 정리한다(`hc ls`에는 사용자의 다른 터미널도 나온다). `hc ls --json`에 `<작업 이름>-`로 시작하는 이름이 남지 않으면 정리가 끝난 것이다. `hc server stop`이나 코어 재시작은 사용자의 다른 터미널까지 끊으므로 하지 않는다.

## worktree 지우기

`git -C <메인 저장소> worktree remove <worktree 경로>` 뒤 `git -C <메인 저장소> branch -D <작업 이름>-<slug>`. squash·rebase 병합이면 `-d`가 병합 안 된 브랜치로 보고 거부하므로 `-D`를 쓴다. 병합됐는지는 SKILL.md 6단계의 확인으로 이미 봤다.

## 작업자가 보고하는 방법

명세 양식의 `{실행 환경: 완료 보고}`와 `{실행 환경: 질문}`에 넣는 문장이다. `<관리자>`에는 실제 주소를 쓴다.

- 완료 보고(구현자): "완료 보고는 `<작업 폴더 절대 경로>/impl-report.md`에 쓰고, `hc send <관리자> \"완료: <그 파일 경로>\"`로 알린다. 막혔을 때도 같은 방법으로 알린다. 이 명령은 관리자에게 보내는 것이지 다른 에이전트를 띄우는 것이 아니다. 하위 에이전트는 띄우지 않는다."
- 완료 보고(검토자): "보고서를 다 쓰면 `hc send <관리자> \"완료: <보고서 경로> 결론 <통과 또는 수정 필요>\"`로 알린다. 하위 에이전트는 띄우지 않는다."
- 질문: "질문은 `hc send <관리자> \"질문: <내용>\"`으로 보내고 턴을 끝낸다. 답은 다음 입력으로 온다."

## 화면에 보이기

`hc`로 띄운 작업자는 기본으로 herdr app 창에 보이지 않는다. 사용자가 작업자를 화면에서 보고 싶다고 하면 `herdr-app ls`로 공간 id를 찾아 `hc label <터미널> herdr.space=<id>`를 붙인다. 사용자가 직접 끼어들고 싶으면 `hc attach <터미널>`로 붙을 수 있다고 알린다(`Ctrl+\`로 떨어진다).

## 지휘 현황 패널

관리자 세션에 `HC_TERMINAL_ID`가 있으면 패널과 띠가 `hc ls --json`에서 작업자 활동을 읽는다(`hooks/register.tsx`). 이름이 `<작업 이름>-`로 시작하는 살아 있는 터미널이 그 작업의 작업자이고(위 "띄우기"의 터미널 이름), 상태 `working`은 일하는 중, `blocked`는 입력 대기, `done`·`idle`은 쉼이다. 상태를 알리지 않은 터미널은 "모름"이다. `열기`는 `herdr-app do agent.focus`로 그 터미널을 연다(화면에 붙이지 않은 작업자는 열리지 않을 수 있다. 위 "화면에 보이기").
