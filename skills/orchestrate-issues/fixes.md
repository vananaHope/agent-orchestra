# 수정과 재검토

5단계에서 "지금 고침"이 하나라도 있을 때 쓴다.

## 수정 명세

다음을 적는다.
- 검토 보고서 경로
- 고칠 지적 목록과 고치지 않을 지적 목록
- "수정분 관련 테스트만 돌린다(전체 테스트는 생략)"

## 수정 작업자

수정을 맡기면 `state.md`를 `수정 중`으로 바꾸고 맡김 기록에 한 줄을 더한다([tiers.md](tiers.md)). 수정 명세가 고칠 곳을 구체적으로 짚으므로 새 작업자에게 구현 맥락이 없어도 된다.

- **설계를 다시 잡아야 하는 수정**(차단 지적 등)은 남겨 둔 원래 구현 터미널(`--terminal <handle>`)에 보낸다. 원래 강도를 그대로 쓴다.
- **코어의 그 밖의 수정**은 수정 묶음의 등급을 정해 그 등급의 구현 목록으로 같은 worktree에 새 작업자를 띄운다. 위치와 방향이 정해진 수정만이면 `light`, 정해진 방향대로 여러 곳을 고치면 `standard`다. 목록에서 검토자와 같은 계열은 건너뛴다(같은 계열이 고치고 재검토하지 않게).
- **UI 수정**은 같은 worktree에 새 Claude 작업자(`--agent claude`)를 띄운다.
- 같은 수정이 두 번 반려되면 [tiers.md](tiers.md) "고르기"대로 다음 작업자로 넘긴다.

## 재검토

**재검토는 차단·중요 지적을 고쳤을 때만** 한다.

- 차단·중요 지적을 하나라도 고쳤으면, 수정이 끝난 뒤 같은 검토자 터미널에 재검토를 맡긴다. 양식은 [review-template.md](review-template.md)의 "재검토". 통과할 때까지 반복한다.
- **사소한 지적만 고쳤으면 재검토 없이** 관리자가 직접 확인한다. Claude 절약 모드에서는 이 확인도 Codex 재검토에 맡긴다([limits.md](limits.md)).
  - 수정 diff를 읽고, 지적마다 고쳐졌는지 판정한다.
  - 관련 테스트만 돌린다.
  - 의심스러우면 그때만 재검토를 맡긴다.
  - 확인 결과를 `.local/orchestration/<작업 이름>/minor-check-<k>.md`에 짧게 남긴다.

**완료 기준**: 마지막 재검토 결론이 "통과"이거나, 사소 수정의 관리자 확인 기록이 남았다.
