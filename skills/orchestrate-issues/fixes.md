# 수정과 재검토

5단계에서 "지금 고침"이 하나라도 있을 때 쓴다.

## 수정 명세

다음을 적는다.
- 검토 보고서 경로
- 고칠 지적 목록과 고치지 않을 지적 목록
- "수정분 관련 테스트만 돌린다(전체 테스트는 생략)"

## 수정 작업자

수정 작업자는 구현자와 같은 계열이다(SKILL.md 배치). Codex 수정은 시간과 한도를 아끼려고 강도를 낮춘다.

- 기본은 같은 worktree에 **새 Codex 작업자를 추론 강도 `medium`으로** 띄운다: `worker-start --spec ... --worktree "id:..." --agent codex --model <Codex 설정의 model> --effort medium`. `--model`/`--effort`는 `--terminal`과 함께 쓸 수 없으므로 기존 터미널을 재사용하지 않는다. 수정 명세가 고칠 곳을 구체적으로 짚으므로 구현 맥락이 없어도 된다.
- 예외: 차단 지적처럼 **설계를 다시 잡아야 하는 수정**은 남겨 둔 원래 터미널(`--terminal <handle>`)에 보낸다. 원래 강도를 그대로 쓴다.
- 처음 구현은 Codex 설정의 기본 강도로 한다.

## 재검토

**재검토는 차단·중요 지적을 고쳤을 때만** 한다.

- 차단·중요 지적을 하나라도 고쳤으면, 수정이 끝난 뒤 같은 검토자 터미널에 재검토를 맡긴다. 양식은 [review-template.md](review-template.md)의 "재검토". 통과할 때까지 반복한다.
- **사소한 지적만 고쳤으면 재검토 없이** 관리자가 직접 확인한다. Claude 절약 모드에서는 이 확인도 Codex 재검토에 맡긴다([limits.md](limits.md)).
  - 수정 diff를 읽고, 지적마다 고쳐졌는지 판정한다.
  - 관련 테스트만 돌린다.
  - 의심스러우면 그때만 재검토를 맡긴다.
  - 확인 결과를 `.local/orchestration/<작업 이름>/minor-check-<k>.md`에 짧게 남긴다.

**완료 기준**: 마지막 재검토 결론이 "통과"이거나, 사소 수정의 관리자 확인 기록이 남았다.
