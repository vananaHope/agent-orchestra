# 한도와 모드

측정은 `check-limits` 스킬로 한다. 판정(`ok`/`warning`/`exhausted`/`unknown`)과 보고 형식은 그 스킬을 따른다. 이 파일은 판정에 따라 지휘 배치를 어떻게 바꾸는지 정한다.

## 재는 때

- 지휘를 시작할 때
- 새 작업을 맡기기 직전(직전 측정이 30분 넘게 지났으면)
- 모드를 바꾸거나 되돌리기 직전
- 메모리나 기록에 "한도 소진"이 있을 때
- Claude는 읽기만 하므로 깨어날 때마다 봐도 된다.

## 판정에 따른 처리

- `warning`: 사용률과 초기화 시각을 사용자에게 알린다. Claude면 아래 Claude 절약 모드로 간다.
- `exhausted`: 아래 해당 모드로 전환한다.
- `unknown`: 추측하지 말고 사용자에게 알린다. 그 에이전트에게는 새 작업을 맡기지 않는다.

## 대체 모드: Codex `exhausted`

Codex의 몫을 Claude와 OpenCode Go가 나눈다. 관리자가 스스로 전환하고 사용자에게는 전환 사실만 알린다. 한도가 돌아오면 원래 배치로 복귀하고 알린다.

- 구현: 등급 목록에서 Codex를 건너뛴다([tiers.md](tiers.md) "고르기"). 목록이 다 막히면 위 등급으로 가고, 기본 목록이면 `hard`의 Claude가 받는다.
- 검토: 검토 목록에서 Codex를 건너뛴다([tiers.md](tiers.md) "검토자 고르기"). Claude가 구현한 일처럼 다른 계열이 남지 않으면 새 Claude 검토자가 맡고 OpenCode `plan` 에이전트의 2차 의견을 함께 받는다(같은 규칙의 2).
- 해당 PR 본문에 "대체 모드(Codex 한도 소진)로 구현·검토"라고 적는다.

## Claude 절약 모드: Claude `warning` 또는 `exhausted`

Claude의 몫을 Codex와 OpenCode Go가 나눈다. 관리자도 Claude이므로 관리자 자신의 일을 줄이는 것이 먼저다. 전환 사실과 측정 숫자를 사용자에게 알린다. 한도가 `ok`로 돌아오면 원래 배치로 복귀하고 알린다.

- 관리자: 직접 diff를 읽는 확인(`light` 확인, 사소 수정 확인, UI 다듬기)을 하지 않는다. 그 확인도 Codex 검토에 맡긴다. 깨어나면 메시지 처리·판정·병합만 한다.
- 검토: 검토 목록에서 `관리자`와 Claude를 건너뛴다([tiers.md](tiers.md) "검토자 고르기"). Codex가 구현한 일처럼 다른 계열이 남지 않으면 **새 Codex 검토자**가 맡고 OpenCode `plan` 에이전트의 2차 의견을 함께 받는다(같은 규칙의 2).
- UI 구현: 새 UI 이슈는 시작하지 않고 Claude 한도가 돌아올 때까지 미룬다. 이미 진행 중인 Claude 작업은 멈추지 않는다.
- 코어 구현: 등급 목록에서 Claude를 건너뛴다.
- **5시간 창이 `exhausted`가 되면 관리자도 멈춘다.** 그 전에(`warning`에서) 진행 중인 작업과 다음 순서를 사용자에게 보고하고, 초기화 시각 뒤에 이어 가겠다고 알린다. 7일 창이 `exhausted`면 사용자에게 계속할지 묻는다.
- 해당 PR 본문에 "Claude 절약 모드(Claude 한도 경고)로 검토"라고 적는다.

## 둘 다 `exhausted`

새 작업을 시작하지 않는다. 진행 중인 작업 목록과 각 한도의 초기화 시각을 사용자에게 보고하고, 등급 목록에서 OpenCode가 맡을 수 있는 일만 이어 갈지 묻는다. 이어 가더라도 검토자가 없으므로 결과는 한도가 돌아온 뒤 검토한다.
